# Getting help

Soloblog is made by one person, ZRPlus Studio. Here's where to go, and
what to expect.

| You want to | Go to |
|---|---|
| Find out how something works | The [user guide](docs/guide/README.md) and the [FAQ](docs/FAQ.md) - also in your admin, under Help |
| Ask a question | [Discussions > Q&A](https://github.com/soloblog/soloblog/discussions/categories/q-a) |
| Suggest an idea | [Discussions > Ideas](https://github.com/soloblog/soloblog/discussions/categories/ideas) - others can upvote it |
| Report something broken | [Issues > Bug report](https://github.com/soloblog/soloblog/issues/new/choose), or **Report a problem** at the bottom of any Settings tab |
| Report a security problem | Privately, through the [Security tab](https://github.com/soloblog/soloblog/security/advisories/new) - never an issue. See [SECURITY.md](SECURITY.md) |
| See what's coming | The [roadmap](docs/ROADMAP.md) |
| See what changed | The [changelog](CHANGELOG.md), or **What's new** in your admin |

**What to expect**

- Everything that comes in is read every week, and gets an answer -
  even if the answer is "not yet" or "no, and here's why".
- Security reports are answered within 3 days and fixed first.
- Fixes go into the latest release. Updating is always safe from any
  earlier version straight to the latest, so that's the one to be on.
- New releases come when they're ready; there are no promised dates. The
  admin tells you when one is out, and **What's new** shows what changed.

**Before you report a bug**, check
[Troubleshooting](docs/guide/troubleshooting.md). The bug form asks
for your version (bottom of any Settings tab), how you host Soloblog,
and the steps that show the problem - with those, it can usually be
fixed quickly.

If Soloblog ever stops being developed, your site keeps running - see
[the FAQ](docs/FAQ.md#what-if-soloblog-stops-being-developed).
